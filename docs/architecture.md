# Архитектура «Симулятора экономики деревень D&D»

## Общие сведения

Локальное настольное приложение на Python. Стек (фактически установленные версии):
Python 3.11.9, CustomTkinter 6.0.0, SQLAlchemy 2.0.30 (SQLite), NetworkX 3.6.1,
Matplotlib 3.9.0, Pytest 8.3.1.

## Слои

| Слой | Модули | Ответственность |
|------|--------|-----------------|
| Представление | `app/ui/*`, `app/visualization/*` | Интерфейс (CustomTkinter), карта мира (NetworkX), графики (Matplotlib). Без SQL и экономических расчётов. |
| Приложение | `app/services.py` | Координация сценариев, вся работа с БД от имени UI, валидация на границе. |
| Домен/экономика | `app/economy/*`, `app/trading/*` | Валюта (целые медные монеты), цены, решения торговцев, переговоры. Чистые функции, тестируемые без БД. |
| Симуляция | `app/simulation/*` | Автономный движок тиков (производство, потребление, цены, торговцы, движение) и игровые часы в фоновом потоке. |
| Инфраструктура | `app/core/*`, `app/database/*` | Конфигурация, сессии SQLAlchemy, схема, журнал. |

## База данных

SQLite-файл `data/campaign.db`. Сущности: `Campaign`, `Settlement`, `Resource`,
`SettlementInventory`, `Trader`, `TraderCargo`, `TradeRoute`, `TradeTransaction`,
`Negotiation`, `EconomicEvent`, `PriceHistory`. Внешние ключи с `ON DELETE CASCADE`,
`PRAGMA foreign_keys=ON` на каждом соединении. Денежные значения — целые медные
монеты (`*_copper`), без float.

Игровое время — целое число часов `Campaign.game_hour`; статус и скорость симуляции
хранятся в БД, поэтому симуляция возобновляется после перезапуска.

## Потоки

- Главный поток: Tkinter/CustomTkinter только через `root.after(...)`.
- Фоновый поток `SimulationClock`: выполняет тики движка под замком, пишет в БД
  короткими сессиями. GUI опрашивает состояние по таймеру, прямых вызовов виджетов
  из фонового потока нет.

## Экономика

- Цена: постепенная реакция на спрос/предложение (`price_engine.compute_price`),
  ограничена `[base*min_factor, base*max_factor]`, детерминирована.
- Производство/потребление за тик ограничены складом и не дают отрицательного остатка.
- Торговец: оценивает маршруты, цены, затраты, риск; покупает только при
  достатке капитала и груза; ожидаемая прибыль сравнивается с порогом;
  отправляется в путь по включённому маршруту, платит транспортные, прибытие
  регистрируется, товар продаётся с учётом переговоров.
- Переговоры: конечное число раундов, границы цены, история и причина результата.

## Тесты

`tests/` — юниттесты валюты, цен, решений торговцев, переговоров; интеграционные
тесты схемы БД, персистентности, тика симуляции, транзакций игроков. Тесты
используют временные БД в `tmp_path`.
