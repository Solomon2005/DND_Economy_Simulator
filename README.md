# Симулятор экономики деревень D&D

Локальное настольное приложение для создания и симуляции экономики поселений,
торговых маршрутов и торговцев в мире Dungeons & Dragons. Все данные хранятся
в локальной базе SQLite; после установки зависимостей интернет не нужен.

## Возможности

- **Поселения** — создание, редактирование и удаление; типы: деревня, городок,
  город, порт, крепость, рудничный посёлок, торговый пост.
- **Ресурсы** — название, категория, единица измерения и базовая цена.
- **Склады** — остатки, ёмкость, производство и потребление за сутки, текущие
  цены и ручные корректировки с записью в журнал.
- **Маршруты** — двусторонние связи между поселениями: расстояние, время в пути,
  транспортные издержки, вместимость, риск и сезонное ограничение.
- **Торговцы** — оценивают цены, маршруты, издержки и риск, торгуются, покупают
  товар, едут по маршруту и продают его по прибытии.
- **Симуляция** — игровые часы в фоновом потоке, скорости `1x`–`50x`,
  старт, пауза, стоп и ручной переход времени.
- **Сделки игроков** — покупки и продажи отряда с полным влиянием на экономику
  или только для учёта.
- **История** — журнал событий с фильтрами по категории, поселению и тексту.
- **Карта мира** — поселения и маршруты; щелчок показывает информацию,
  перетаскивание меняет положение иконки.
- **Отчёты и графики** — история цен, объём сделок по суткам, балансы поселений
  и капиталы торговцев; экспорт журнала в CSV.
- **Настройки** — параметры экономики, тема оформления и резервные копии.

## Системные требования

- Windows, Linux или macOS с графической средой (Tkinter).
- Python 3.11+ (проверено на Python 3.11.9).
- Зависимости из `requirements.txt`: CustomTkinter, SQLAlchemy, NetworkX,
  Matplotlib и вспомогательные библиотеки.
- Интернет нужен только для установки зависимостей.

## Установка

Все команды выполняются из папки проекта.

1. При необходимости создайте виртуальное окружение:

   Windows:

   ```bat
   python -m venv .venv
   .venv\Scripts\activate
   ```

   Linux/macOS:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

   На Linux/macOS используйте `python3 -m pip install -r requirements.txt`.

## Запуск приложения

### Windows

- `run.bat` — запуск без окна консоли.
- `python launcher.py` — запуск с проверкой зависимостей.
- `python create_shortcut.py` — создать ярлык «Симулятор экономики D&D»
  в папке проекта.

### Linux/macOS

```bash
./run.sh
```

или:

```bash
python3 launcher.py
```

`launcher.py` проверяет наличие основных библиотек и сообщает, каких не хватает,
после чего запускает `main.py`.

### Первый запуск

При первом запуске автоматически создаются:

- база данных `data/campaign.db`;
- папки `data/backups/` и `data/exports/`;
- файл настроек `config.json`;
- основная кампания, если её ещё нет;
- демо-мир, если в кампании нет поселений: три деревни, два города, три
  ресурса, склады, маршруты и торговцы.

Демо-мир позволяет сразу запустить симуляцию: откройте раздел **Симуляция**
и нажмите **▶ Старт**. При обычном запуске данные кампании не удаляются.

При запуске приложение проверяет целостность базы и не чаще раза в сутки
создаёт резервную копию.

## Начало работы

### Быстрый старт на демо-мире

1. Откройте **Симуляция**.
2. Нажмите **▶ Старт**.
3. Дождитесь нескольких тиков и посмотрите **Историю**, **Отчёты** и карту
   на вкладке **Главная**.

По умолчанию один тик — это 6 игровых часов, а при скорости `1x` он выполняется
раз в 2 реальные секунды.

### Пример своего мира: «Пшеничный путь»

1. **Поселения**: создайте `Дубравку` (деревня, население `120`) и
   `Рынок на перекрёстке` (городок, население `900`).
2. **Ресурсы**: создайте `Пшеницу`, категория `Еда`, единица `мешок`,
   базовая цена `1 gp`.
3. **Склады**:
   - в Дубравке добавьте пшеницу: производство `240`/сут, потребление `0`,
     цена `50` CP, ёмкость `500`, затем скорректируйте остаток на `+200`;
   - на рынке добавьте пшеницу: производство `0`, потребление `240`/сут,
     цена `1 gp`, ёмкость `500`, остаток можно оставить `0`.
4. **Маршруты**: создайте маршрут между поселениями: расстояние `20` км,
   время в пути `12` ч, издержки `2` CP за единицу, вместимость `100`,
   риск `0.05`, сезон оставьте пустым.
5. **Торговцы**: создайте `Ивана` с домом в Дубравке и капиталом `100 gp`.
6. **Симуляция**: нажмите **▶ Старт**. Торговец купит пшеницу, выедет на рынок,
   продаст товар и вернётся домой.

## Руководство по использованию

### Главное окно

Слева расположена навигация по разделам:

| Раздел | Для чего нужен |
|---|---|
| **Главная** | Сводка, карта мира и очистка истории |
| **Поселения** | Создание и редактирование поселений |
| **Ресурсы** | Справочник товаров |
| **Склады** | Остатки, производство, потребление и цены |
| **Маршруты** | Торговые связи между поселениями |
| **Торговцы** | Создание торговцев и управление капиталом |
| **Симуляция** | Управление игровым временем |
| **Сделки игроков** | Ручная запись покупок и продаж отряда |
| **История** | Журнал экономических событий |
| **Отчёты** | Сводка, графики и экспорт CSV |
| **Настройки** | Параметры экономики, тема и резервные копии |

Данные перечитываются при переключении раздела, поэтому новые поселения,
ресурсы и маршруты сразу доступны в других разделах.

На вкладке **Главная** есть кнопка **Очистить историю**. После подтверждения
она удаляет сделки, историю цен, переговоры и журнал событий. Поселения,
склады, торговцы, маршруты и капиталы остаются без изменений. Действие
необратимо.

### Поселения

Поля:

- **Название** — обязательное и уникальное в кампании;
- **Тип** — деревня, городок, город, порт, крепость, рудничный посёлок или
  торговый пост;
- **Население** — целое число;
- **Описание** — задаётся в окне **Изменить выбранный**.

Кнопки: **Создать**, **Изменить выбранный**, **Удалить выбранный**.

При удалении поселения удаляются его склады и связанные маршруты. Если
к поселению привязаны торговцы (дом или текущее местоположение), удаление
будет отклонено — сначала удалите этих торговцев.

### Ресурсы

Поля: **Название**, **Категория**, **Единица**, **Базовая цена**.

Кнопки: **Создать**, **Изменить выбранный**, **Удалить выбранный**.

Ресурс нельзя удалить, если он есть на складах поселений или в грузе
торговцев. Сначала уберите его со складов и дождитесь продажи груза.

### Склады

Склад — это рынок конкретного ресурса в конкретном поселении.

Таблица показывает склады всех поселений. Список **Поселение** вверху нужен
только для добавления новой позиции. Чтобы изменить существующую позицию,
выберите её строку в таблице, заполните поля и нажмите
**Применить к выбранной**.

Поля:

| Поле | Значение |
|---|---|
| **Поселение** | Где находится склад (столбец таблицы) |
| **Ресурс** | Какой товар хранится |
| **Произв./сут** | Сколько единиц производится за игровые сутки |
| **Потребл./сут** | Сколько единиц потребляется за игровые сутки |
| **Цена** | Текущая рыночная цена за единицу |
| **Склад, ед.** | Максимальная ёмкость |

Кнопки:

- **Добавить на склад** — открыть позицию в выбранном поселении;
- **Применить к выбранной** — сохранить параметры выбранной строки;
- **Скорректировать** — изменить остаток на `+N` или `-N`;
- **Снять позицию** — удалить ресурс со склада.

Правила:

- производство не превышает ёмкость склада и учитывает сезонный множитель,
  если он включён;
- потребление не уводит остаток ниже нуля;
- цена меняется постепенно при дисбалансе спроса и предложения и ограничена
  настройками (по умолчанию от `0.5` до `3.0` базовой цены);
- ёмкость нельзя сделать меньше текущего остатка;
- ручные корректировки и правки капитала попадают в журнал.

### Маршруты

Маршрут — **двусторонняя** связь между двумя поселениями. Одна запись
описывает движение в обе стороны, поэтому отдельный обратный маршрут
создавать не нужно.

Поля:

| Поле | Значение |
|---|---|
| **Поселение 1** | Первый конец маршрута |
| **Поселение 2** | Второй конец маршрута |
| **Расстояние, км** | Справочное значение |
| **Часов в пути** | Сколько игровых часов занимает поездка |
| **Издержки за ед., CP** | Транспортные расходы за единицу груза |
| **Вместимость** | Максимум единиц за один рейс |
| **Риск (0..1)** | Снижает ожидаемую прибыль |
| **Сезон** | Ограничение сезона; пусто — круглый год |

Сезон можно указывать по-русски или по-английски: `зима`/`winter`,
`весна`/`spring`, `лето`/`summer`, `осень`/`autumn`. Если сезон указан,
маршрут работает только в него.

Кнопки: **Создать**, **Вкл/выкл выбранный**, **Удалить выбранный**.
Дубликаты запрещены: повторный маршрут между теми же поселениями в обратном
направлении создать нельзя.

### Торговцы и торговля

Поля:

- **Имя** — уникальное в кампании;
- **Дом** — поселение, куда торговец возвращается;
- **Капитал** — стартовые деньги.

Кнопки: **Создать**, **Капитал ±**, **Удалить выбранный**.
Кнопка **Капитал ±** принимает изменение в CP: например, `500` или `-200`.

Значения по умолчанию: грузоподъёмность `50` единиц, минимальная маржа `15%`,
навык торга `0.5`. Отдельного выбора стратегии в интерфейсе нет — движок сам
оценивает сделки по единым правилам.

На каждом тике торговец:

1. Проверяет, есть ли рядом включённые маршруты.
2. Ищет товар в текущем поселении.
3. Сравнивает цену закупки и цену продажи в соседнем поселении.
4. Учитывает транспортные издержки и риск.
5. Проверяет капитал, свободное место в грузе, свободное место на складе
   назначения и вместимость маршрута.
6. Если ожидаемая прибыль достаточна — покупает товар и выезжает.
7. По прибытии продаёт товар, при необходимости торгуясь о цене.
8. Если прибыльных вариантов нет — возвращается домой.

Минимальные условия сделки:

- цена продажи выше цены закупки;
- прибыль не меньше `10 CP`;
- прибыль не меньше `15%` от суммы закупки;
- хватает капитала;
- есть свободное место в грузе и на складе назначения;
- в поселении назначения есть рынок этого ресурса.

Пример расчёта:

```text
Закупка: 50 CP/ед., продажа: 100 CP/ед., транспорт: 2 CP/ед.
Количество: 50, риск: 0.05

Валовая прибыль  = 50 × (100 − 50) = 2500 CP
Транспорт        = 50 × 2 = 100 CP
Прибыль до риска = 2500 − 100 = 2400 CP
Поправка на риск = 2400 × (1 − 0.05 × 0.5) = 2340 CP
Порог по марже   = 2500 × 0.15 = 375 CP
```

Прибыль `2340 CP` больше порога, поэтому сделка принимается. Итоговая цена
может измениться после переговоров.

Если торговец стоит на месте, проверьте: есть ли товар на складе, включён ли
маршрут, не мешает ли сезон, хватает ли капитала, есть ли свободное место
на складе назначения и достаточно ли прибыли. Причины отказа по возможностям
пишутся в `data/simulation.log`, а срыв переговоров — в журнал категорией
**Сбой сделки**.

### Симуляция

Кнопки:

- **▶ Старт** — запустить фоновые тики;
- **⏸ Пауза** — остановить новые тики, состояние сохраняется;
- **⏹ Стоп** — остановить симуляцию;
- **Скорость** — `1x`, `2x`, `5x`, `10x`, `50x`;
- **+1 час**, **+1 день**, **+1 неделя**, **+1 месяц** — ручной переход;
- **Шаг (+6 ч)** — один тик вручную (по умолчанию 6 игровых часов).

Ручной переход доступен на паузе и при остановке. Если нажать его при
запущенной симуляции, приложение попросит сначала поставить паузу или
остановить симуляцию.

Статусы:

| Статус | Значение |
|---|---|
| `▶ запущена` | Тики выполняются |
| `⏸ пауза` | Тики не выполняются, время стоит |
| `⏹ стоп` | Симуляция остановлена |
| `⚠ ошибка` | В фоновом тике произошла ошибка |

При статусе `⚠ ошибка` посмотрите текст на панели и файл `data/simulation.log`.
После устранения причины нажмите **▶ Старт** снова.

Симуляция работает в отдельном потоке, поэтому интерфейс не замерзает.
Состояние кампании, игровое время, статус и скорость сохраняются в базе;
после перезапуска приложения симуляция продолжается с сохранённого места,
если её статус был «запущена».

### Сделки игроков

Здесь записываются покупки и продажи отряда.

Поля:

- **Поселение** — где произошла сделка;
- **Ресурс** — что купили или продали;
- **Тип** — «Игроки купили» или «Игроки продали»;
- **Количество** — целое число;
- **Цена за ед.** — например, `1 gp 5 sp`;
- **Покупатель/продавец** — контрагент;
- **Режим**:
  - **Полное влияние на экономику** — меняет склад поселения, цена
    пересчитывается при следующем тике;
  - **Только учёт (без склада)** — записывает сделку в книгу, но не трогает
    склад;
- **Описание** — комментарий.

Кнопка **Записать сделку** сохраняет операцию.

Пример: отряд покупает 10 мешков пшеницы по `1 gp 5 sp` в режиме полного
влияния. Итог: 150 CP за единицу, всего 1500 CP. Склад уменьшится на 10,
событие попадёт в журнал.

### История

Журнал событий с фильтрами:

- **Категория** — производство, потребление, закупка, продажа, сбой сделки,
  выезд/прибытие торговца, изменение цены, сделка игроков, ручная правка;
- **Поселение**;
- **Поиск** — текст по описанию.

Кнопка **Найти** применяет фильтры. Записи содержат дату, категорию,
поселение, торговца и описание.

Кнопка **Сбросить историю** удаляет все записи журнала кампании после
подтверждения. Склады, торговцы и сделки при этом не меняются.

Если торговец не совершает сделку, ищите категорию **Сбой сделки** (срыв
переговоров) и смотрите причину: нет капитала, нет товара, низкая прибыль,
нет склада и т. п. Остальные причины отказа пишутся в `data/simulation.log`.

### Карта мира

Карта расположена на вкладке **Главная** под сводкой показателей.

- Зелёная сплошная линия — включённый маршрут.
- Серая пунктирная — отключённый.
- Подпись `12ч` — время в пути.
- `♟ N` — количество торговцев в поселении.
- Щелчок по поселению показывает справа склад, торговцев и маршруты.
- Зажмите левую кнопку мыши на иконке и перетащите её — положение сохранится
  при обновлении карты до перезапуска приложения.

Маршруты на карте неориентированные: линия без стрелки означает движение
в обе стороны.

### Отчёты и графики

- **Обновить сводку** — пересчитать показатели;
- **Экспорт журнала в CSV** — сохранить события в `data/exports/events.csv`.

Сводка показывает количество сделок и событий, топ ресурсов по объёму сделок,
балансы поселений и капиталы торговцев.

На графиках можно выбрать ресурс и поселение, затем нажать
**Обновить графики**:

- история цены ресурса;
- объём сделок по игровым суткам.

Графики строятся по реальным данным. CSV сохраняется в UTF-8 с BOM и
открывается в Excel.

### Настройки

Параметры экономики:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| Скорость реакции цены | `0.06` | Насколько быстро цена реагирует на дисбаланс |
| Мин. цена от базовой | `0.5` | Нижняя граница цены |
| Макс. цена от базовой | `3.0` | Верхняя граница цены |
| Игровых часов в тике | `6` | Сколько времени проходит за тик |
| Реальных секунд на тик (1x) | `2.0` | Пауза между тиками при 1x |
| Макс. раундов торга | `5` | Сколько раундов может длиться торг |
| Склад по умолчанию, ед. | `500` | Ёмкость нового склада |

Флажки:

- **Сезонные множители производства** — зима `0.7`, лето `1.1`;
- **Писать производство/потребление раз в сутки** — не засорять журнал.

Режим сделок игроков по умолчанию: «Полное влияние» или «Только учёт».

Кнопка **Сохранить настройки** записывает `config.json`. Новые параметры
подхватываются работающими часами симуляции. Тема оформления применяется
сразу и сохраняется вместе с остальными настройками.

Дополнительный параметр `price_history_days` (по умолчанию `90`) задаётся
в `config.json` вручную и ограничивает глубину истории цен.

Резервные копии:

- **Создать копию** — вручную сохранить базу в `data/backups/`;
- **Восстановить последнюю** — восстановить самую новую копию.

## Сезоны и время

Игровой календарь: 12 месяцев по 30 дней, 24 часа в сутках. Старт кампании —
январь, зима.

| Месяцы | Сезон | Множитель производства |
|---|---|---|
| Декабрь–февраль | Зима | 0.7 |
| Март–май | Весна | 1.0 |
| Июнь–август | Лето | 1.1 |
| Сентябрь–ноябрь | Осень | 1.0 |

Сезонные множители применяются, если включён флажок в настройках. Маршрут
с ограничением `зима` работает только в декабре, январе и феврале.

## Резервное копирование и восстановление

- При запуске приложение автоматически создаёт копию базы не чаще раза в сутки.
- Вручную копия создаётся в **Настройки** → **Создать копию**.
- **Восстановить последнюю** восстанавливает самую новую копию из
  `data/backups/`.
- На время восстановления симуляция приостанавливается, затем запускается
  снова, если работала до этого.
- Существующие копии никогда не перезаписываются.
- Если восстановление не удалось, приложение возвращает текущую базу
  из страховочной копии.
- После восстановления переключите раздел, чтобы данные перечитались.
  Если данные не обновились, перезапустите приложение.

Перед крупными изменениями делайте резервную копию. Не удаляйте
`data/campaign.db`, если хотите сохранить кампанию.

## Где хранятся данные

| Что | Где |
|---|---|
| База кампании | `data/campaign.db` |
| Резервные копии | `data/backups/campaign_*.db` |
| Экспорт CSV | `data/exports/events.csv` |
| Настройки | `config.json` в папке проекта |
| Диагностика симуляции | `data/simulation.log` |

Все суммы в базе хранятся в целых медных монетах (CP): `1 SP = 10 CP`,
`1 GP = 100 CP`, `1 PP = 1000 CP`. Ввод понимает также `EP = 50 CP`;
на экране суммы отображаются в GP/SP/CP.

## Решение распространённых проблем

| Проблема | Вероятная причина | Решение |
|---|---|---|
| Новое поселение не видно в другом разделе | Раздел ещё не перечитал данные | Переключитесь на нужный раздел |
| Не создаётся обратный маршрут | Маршрут уже двусторонний | Используйте существующий маршрут |
| Торговец стоит на месте | Нет товара, маршрута, капитала или прибыли | Проверьте склад, маршрут, сезон, капитал и `data/simulation.log` |
| Симуляция «запущена», но время стоит | Статус `⚠ ошибка` | Посмотрите текст ошибки и лог, затем нажмите «Старт» |
| Цена не меняется | Нет дисбаланса спроса и предложения | Задайте производство или потребление, измените `price_k` |
| Не удаляется ресурс | Он есть на складе или в грузе торговца | Уберите его со складов и дождитесь продажи груза |
| Не удаляется поселение | К нему привязаны торговцы | Удалите или перенесите торговцев; маршруты удалятся сами |
| Не восстанавливается база | Нет копий или база занята | Проверьте `data/backups/`, закройте лишние программы и повторите |
| После восстановления старые данные | Раздел ещё не перечитал базу | Переключите раздел или перезапустите приложение |
| Приложение не запускается | Не установлены зависимости или ошибка `config.json` | Запустите `python launcher.py`, проверьте JSON в `config.json` |
| Графики пустые | Ещё не было тиков или изменений цен | Запустите симуляцию и дождитесь нескольких тиков |

## Шпаргалка по значениям

|---|---|
| 100 медных монет | `100` или `100 cp` |

## Ограничения

- Приложение рассчитано на одну локальную кампанию; выбора кампаний
  в интерфейсе нет.
- Демо-мир создаётся только для пустой кампании. Если поселения уже есть,
  новые автоматически не добавляются.
- История цен хранится 90 игровых суток по умолчанию.
- Симуляция идёт только при запущенном приложении.
- Положение иконок на карте сохраняется до перезапуска приложения.
- Восстановление доступно только из последней резервной копии; выбрать
  другую копию в интерфейсе нельзя.
- Очистка истории необратима.
